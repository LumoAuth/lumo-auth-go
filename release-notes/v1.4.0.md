## Highlights & New Features

### 1. Token and Cost Usage Reporting (`github.com/lumoauth/lumo-auth-go`)

LumoAuth does not see an agent's model calls. Agents can now report the tokens and cost of their model calls, so that the token and cost limits of the agent's budget (`max_tokens_per_hour`, `max_tokens_per_day`, `max_cost_per_day_usd`, `max_cost_per_month_usd`) count real usage.

- Added `AgentsResource.ReportUsage(ctx, tokens, costUSD)` (`resource_agents.go`). It sends `{"tokens", "cost_usd"}` to `POST /orgs/{orgId}/api/v1/agents/me/usage`, registered as the new `RouteAgentsReportUsage` route (`agents.reportUsage`) in `routes.go`.
- Added `Agent.ReportUsage(ctx, tokens, costUSD)` (`agent.go`). The budget in the result replaces the cached budget, so `CheckBudget` reflects the report without another request.
- The SDK checks the report before it sends a request. It returns a `*ValidationError` that matches `ErrValidation` in these cases:
  - `tokens` is negative.
  - `costUSD` is negative, `NaN` or infinite.
  - Both values are zero.
- Added two result types in `types.go`:
  - `UsageReportResult` has `Recorded` and `Budget`. `Budget` is the agent's budget after the report, in the same shape as `BudgetPolicy` in `UserInfo`. When `Budget.Exhausted()` is true, the next metered call (Ask API call, token request or JIT request) gets HTTP 429.
  - `RecordedUsage` has `Tokens` and `CostUSD`: the tokens and cost that the server added.
- A report is not a metered call. The server accepts it even when the budget is spent.
- Only agent credentials can report usage. A `Client` also has `Agents.ReportUsage`, but the server answers other tokens and portal test tokens with 403.
- The server limits how often each agent can report (429 `rate_limited`). If your agent calls models often, send fewer, larger reports.

```go
resp, err := llm.Chat(ctx, req)
if err != nil {
	return err
}

if _, err := agent.ReportUsage(ctx, resp.Usage.TotalTokens, 0.0042); err != nil {
	return err
}

// Uses the budget from the report; no extra request.
if err := agent.CheckBudget(ctx); err != nil {
	return err // matches ErrBudgetExceeded: the next Ask, token or JIT request gets 429
}
```

### 2. Capability Matching Like the Server (`capability.go`)

Capability checks in the SDK compared strings with `==`, so they could disagree with the server. The server stores `tool:search_web` as `tool.search_web`, and a held `invoices.*` covers `invoices.read`. The SDK now uses the server's rules.

- Added three functions in `capability.go`:
  - `NormalizeCapability(capability)` returns the stored form. It trims the name, lower-cases ASCII letters, turns `:` and `-` into `.`, collapses runs of `.` and trims `.` from both ends. `"Invoices:Read"` and `"invoices-read"` both become `"invoices.read"`.
  - `CapabilityCovers(capability, action)` reports whether one capability covers an action, in any spelling of either. `*` covers every action. A name that ends in `.*` covers every action under that prefix at any depth, but not the prefix itself: `invoices.*` covers `invoices.read.draft`, not `invoices`.
  - `AnyCapabilityCovers(capabilities, action)` checks a list.
- These checks now use the new rules:
  - `Agent.HasCapability` (`agent.go`)
  - `Agent.RequireCapability`, through `HasCapability` (`agent.go`)
  - `AccessTokenClaims.HasCapability` for verified tokens (`access_token_verify.go`)
- `AccessTokenClaims.HasScope` still compares scopes exactly.
- `HasCapability` reads only the agent's registered capabilities. The Ask API (`Agent.Ask`) also applies your policies and the token's scope.

```go
lumoauth.NormalizeCapability("Tool:Search-Web")        // "tool.search.web"
lumoauth.CapabilityCovers("users:*", "USERS-DELETE")   // true
lumoauth.CapabilityCovers("invoices.*", "invoices")    // false
```

### 3. `AgentBudget.Exhausted()` Covers Every Limit (`types.go`)

- Added `AgentBudget.ReportedExhausted` (`*bool`, JSON `exhausted`). The server sets it to `true` when any limit is reached: calls, tokens or cost, per hour, day or month. It is `nil` when the server does not send it.
- `AgentBudget.Exhausted()` now returns `ReportedExhausted` when the server sent it. Otherwise it compares the daily token cap with today's usage, as in v1.3.0.
- `Agent.CheckBudget` uses `Exhausted()`, so it follows the same rules.
- The other budget fields, such as call and cost limits and their usage, are in `AgentBudget.Raw`.

## Upgrade Notes

- **Capability checks can now return `true` where v1.3.0 returned `false`.** An agent that holds `tool.search_web` now passes `HasCapability(ctx, "tool:search_web")`, and an agent that holds `tool.*` now passes `HasCapability(ctx, "tool.search_web")`. This change also applies to `RequireCapability` and to `AccessTokenClaims.HasCapability` in MCP servers. The new answers match the server's. Review any code that relied on an exact string comparison.
- **`CheckBudget` can now return `ErrBudgetExceeded` before the daily token cap is reached.** Call limits, hourly limits and cost limits also count now.
- No dependency changes in this release. The module still requires Go 1.22.
