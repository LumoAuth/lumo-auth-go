## Fixes

### 1. `RouteWebMagicLink` Points to the Sign-In Link API (`routes.go`)

- `Routes[RouteWebMagicLink]` (`web.magicLink`) is now `POST /orgs/{orgId}/api/v1/oauth/magic-link`.
- Before, the route was `POST /orgs/{orgId}/magic-link`. That path is the form endpoint of the hosted login page. It accepts a request only from the hosted page itself, so the server refused every request that your own code sent there.
- No SDK method calls this route. The change affects only code that reads the route table directly, through `RoutePath`, `BuildPath` or `Routes`.
- `RouteWebCheckEmail` (`web.checkEmail`) did not change. It still points to `POST /orgs/{orgId}/check-email`.
- The route table now matches the JavaScript SDK v1.5.0, which calls the same endpoint from `requestMagicLink()`.

The new endpoint is for apps that render their own sign-in form. It mails a single-use sign-in link to the address. It does not sign anybody in and does not issue tokens. The person opens the link, confirms on the hosted page and then goes to `return_to`. On that page, your app starts its normal authorization flow.

The request body is JSON:

| Field | Required | Meaning |
| :--- | :--- | :--- |
| `email` | yes | The address to send the sign-in link to. |
| `client_id` | yes | The client ID of an active application of the organization. |
| `return_to` | no | The page of your app where the person goes after sign-in. It must be an absolute `https` URL (`http` only on localhost), at most 1,024 characters long. Its origin must be an allowed origin of the application or the origin of one of its redirect URIs. Without it, the person goes to the default page of the organization. |
| `captcha_token` | no | The token from the CAPTCHA widget. It is required when the organization protects sign-in link requests with a CAPTCHA. |

The server answers `200` with `{"status":"sent"}`. The answer is the same whether or not the address belongs to an account. A refused request gets `{"error": …, "message": …}`:

| Status | `error` |
| :--- | :--- |
| `400` | `invalid_request`, `invalid_client`, `invalid_return_to`, `captcha_required`, `captcha_failed` |
| `403` | `origin_not_allowed`: a browser sent the request from a page outside the allowed origins of the application. |
| `404` | `not_found` (unknown organization) or `magic_link_disabled` (the organization does not offer sign-in links) |
| `429` | `rate_limited` |

```go
path, err := lumoauth.RoutePath(lumoauth.RouteWebMagicLink,
	map[string]string{"orgId": "acme-corp"})
if err != nil {
	return err
}
// path == "/orgs/acme-corp/api/v1/oauth/magic-link"

body, err := json.Marshal(map[string]string{
	"email":     email,
	"client_id": clientID,
	"return_to": "https://app.example.com/signed-in",
})
if err != nil {
	return err
}

req, err := http.NewRequestWithContext(ctx, http.MethodPost,
	lumoauth.DefaultBaseURL+path, bytes.NewReader(body))
if err != nil {
	return err
}
req.Header.Set("Content-Type", "application/json")
```

## Upgrade Notes

- **Requests built from `RouteWebMagicLink` now go to the API endpoint.** If your code used this route, send the JSON body above instead of the form fields of the hosted page. Read the result from the JSON answer, not from a redirect.
- **Sign-in links must be switched on for the organization.** Otherwise the server answers `404` with `magic_link_disabled`.
- **A request from a browser must come from an allowed origin of the application.** Otherwise the server answers `403` with `origin_not_allowed`.
- `Version` is now `"1.5.0"`, so the default `User-Agent` reports `1.5.0`.
- No dependency changes in this release. The module still requires Go 1.22.
