## Highlights & New Features

### 1. Verify Requests from Personal Agents (`resource_poppy.go`, `poppy_http.go`)

A personal agent that follows the [Personal Agent Protocol](https://personalagentprotocol.org) sends the `Poppy-Session` header to your own API, not to LumoAuth. The new `client.Poppy` resource asks LumoAuth who such a request is from: the personal agent, its user, the Session, and the account when the request carries an access token.

- **The calls authenticate as a confidential application.** The new option `WithClientCredentials(id, secret)` sets its client ID and client secret. The `client.Poppy` calls send them with HTTP Basic. They never send the API key or the bearer token of the client, and no other call sends the client credentials. The allowed scopes of the application must include `poppy:verify`.
- **A client with only client credentials is valid.** It can call `client.Poppy` and nothing else.
- **A refusal is a result, not an error.** `VerifyRequest()` returns a `*PoppyVerification` with `Active` set to `false`. `Error` holds the error code of the protocol, and `Response` holds the status, the headers and the body for the personal agent. Send that response unchanged.
- **An error is about your service.** The calls return `ErrAuthentication` (401), `ErrPermissionDenied` (403), `ErrNotFound` (404), `ErrRateLimited` (429) or `ErrNetwork` when LumoAuth could not be reached or rejected your own application. Never relay such an error to the personal agent.
- **A malformed answer is never read as verified.** A `200` answer that is neither a verified result nor a well-formed refusal gives `ErrValidation`.
- **Only the protocol's headers leave your server.** You may pass every header of the request. The SDK sends five: `Poppy-Session`, `Poppy-Version`, `Poppy-Extensions`, `Authorization` and `DPoP`.

**The middleware.** `client.Poppy.Middleware()` returns `net/http` middleware for the routes that personal agents call.

```go
client, err := lumoauth.New(
    lumoauth.WithOrgID("acme-corp"),
    lumoauth.WithClientCredentials(os.Getenv("SHOP_API_CLIENT_ID"), os.Getenv("SHOP_API_CLIENT_SECRET")),
)
if err != nil {
    log.Fatal(err)
}

verified, err := client.Poppy.Middleware(lumoauth.PoppyMiddlewareOptions{
    PublicOrigin:  os.Getenv("PUBLIC_ORIGIN"), // for example https://shop.example.com
    RequiredScope: []string{"orders:read"},
    OnError: func(w http.ResponseWriter, r *http.Request, err error) {
        log.Printf("Session verification failed: %v", err)
        http.Error(w, "internal error", http.StatusInternalServerError)
    },
})
if err != nil {
    log.Fatal(err) // PublicOrigin or the client credentials are missing
}

mux := http.NewServeMux()
mux.Handle("GET /api/orders", verified(http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
    who, _ := lumoauth.PoppyFromContext(r.Context())
    w.Header().Set("Content-Type", "application/json")
    json.NewEncoder(w).Encode(map[string]any{"account": who.Account.Subject})
})))
```

For each request, the middleware does one of three things:

- **Verified.** It stores the `*PoppyVerification` in the request context and calls the handler. Read it with `PoppyFromContext()`.
- **Refused.** It sends the response of LumoAuth to the personal agent unchanged, and it does not call the handler.
- **The call failed.** It does not call the handler and relays nothing. It calls `OnError`. Without `OnError` it answers `500` with the fixed body `{"error":"server_error"}`. The SDK does not log, so set `OnError` to record the error.

**`PublicOrigin` comes from your configuration.** A Session JWT names the address that the personal agent called. The middleware builds the URL from `PublicOrigin` and the path of the request line (`r.RequestURI`), without the query. It never reads the `Host` header or the `X-Forwarded-*` headers. `http.StripPrefix` or a router prefix in front of the middleware does not shorten the URL.

**Without the middleware.** `VerifyHTTPRequest(ctx, publicOrigin, r, opts)` verifies a `*http.Request` in a handler, and `WritePoppyRefusal(w, verification)` relays a refusal. `VerifyRequest(ctx, PoppyRequest{Method, URL, Headers}, opts)` takes the parts of a request from another router or server. `BuildPoppyVerifyBody()` builds the request body without a call.

**Sessions.** `GetSessionStatus(ctx, personalAgent, sid)` returns a `*PoppySessionStatus` whose `Status` is `PoppyStatusActive`, `PoppyStatusEnded` or `PoppyStatusUnknown`. An unknown Session is a result, not an error. `EndSession(ctx, personalAgent, sid)` returns `false` when the Session had ended before, and `ErrNotFound` for an unknown Session.

New exported names:

- **Options and resource:** `WithClientCredentials`, `PoppyResource`
- **Requests:** `PoppyRequest`, `PoppyVerifyOptions`, `PoppyMiddlewareOptions`, `BuildPoppyVerifyBody`
- **Results:** `PoppyVerification`, `PoppySession`, `PoppyAccount`, `PoppyRelayResponse`, `PoppySessionStatus` and the three `PoppyStatus…` constants
- **HTTP helpers:** `PoppyFromContext`, `ContextWithPoppy`, `WritePoppyRefusal`
- **Routes:** `RoutePoppyVerifyRequest`, `RoutePoppyGetSessionStatus`, `RoutePoppyEndSession`

### 2. Custom Domains (`custom_domain.go`)

An organization can serve LumoAuth on its own domain, for example `https://auth.acme.com`. Before this release, the SDK put `/orgs/{orgId}` in every organization path. A custom domain does not serve such a path, so every call to it got 404. The new option `WithCustomDomain` fixes that.

```go
client, err := lumoauth.New(
    lumoauth.WithCustomDomain("auth.acme.com"), // or "https://auth.acme.com"
    lumoauth.WithAccessToken(os.Getenv("USER_ACCESS_TOKEN")),
)
if err != nil {
    log.Fatal(err) // a ConfigError when the value is not a valid domain
}

// POST https://auth.acme.com/api/v1/abac/check
decision, err := client.Abac.Check(ctx, lumoauth.AbacCheckParams{
    ResourceType: "document",
    Action:       "read",
    ResourceID:   "doc-123",
})

issuer, _ := client.Issuer() // https://auth.acme.com
```

With a custom domain:

- **No path has the `/orgs/...` segment.** A path that never had the segment, such as `/api/v1/authz/check`, stays the same.
- **The organization ID is not needed.** When you set it too, the SDK never puts it in a path.
- **The custom domain wins over the base URL.** `WithBaseURL` and `LUMOAUTH_URL` are not used for any request.
- **The issuer is the bare domain**, `https://auth.acme.com`. A client assertion uses it as the audience. `VerifyAccessToken` with `CustomDomain` accepts exactly that issuer, and an access token that names the platform issuer is refused.

| Where | How you set it |
| :--- | :--- |
| `lumoauth.New` | `WithCustomDomain(domain)`, or `LUMOAUTH_CUSTOM_DOMAIN` |
| `NewAgent`, `NewWebAuth`, `NewAAuthClient` | The `CustomDomain` field of the config struct, or `LUMOAUTH_CUSTOM_DOMAIN` |
| `NewJITContext`, `NewDelegationChain` | Nothing: they follow the agent that you pass |
| `VerifyAccessToken`, `RequireAccessToken` | `AccessTokenVerifyOptions.CustomDomain`, in place of `Issuer` |
| `VerifyAuthToken` | `VerifyOptions.CustomDomain` |
| Key caches | `NewAccessTokenKeyCacheForCustomDomain`, `NewJWKSCacheForCustomDomain` |

- **The value** is a host name or an `https://` origin. The SDK changes it to `https://<host>[:port]` with a lower-case host. `http://` is accepted only for `localhost`, `127.0.0.1` and `[::1]`. A value with a path, a query, a fragment or credentials is a `ConfigError`, which the constructor returns. An empty value means that no custom domain is set.
- **The two token verifiers do not read the environment variable.** Set the field.
- **New methods:** `client.Issuer()`, `client.CustomDomain()`, `agent.CustomDomain()` and `aauth.CustomDomain()`.

**AAuth keeps the platform issuer.** LumoAuth names the AAuth issuer with the platform address on every host, for example `https://app.lumoauth.dev/orgs/acme-corp/api/v1`. An AAuth token carries that address as `iss`, and an agent addresses it as the audience. So the SDK sends AAuth requests to the custom domain, but it never derives the AAuth issuer from the domain.

- The new method `aauth.ResolveIssuer(ctx)` returns the AAuth issuer. With a custom domain it reads the `issuer` member of `https://auth.acme.com/api/v1/.well-known/aauth-issuer` once.
- `aauth.Issuer()` makes no request. With a custom domain it returns an empty string until `ResolveIssuer` has run.
- `VerifyAuthToken` with `VerifyOptions.CustomDomain` reads the trusted issuer from the same document and keeps it for one hour. It reads the keys from `https://auth.acme.com/api/v1/aauth/jwks.json`. A token that names the bare domain is refused.
- Set `AAuthConfig.Issuer` or `VerifyOptions.Issuer` to name the AAuth issuer yourself. The SDK then does not read the document.

**Paths that you write yourself.**

- `client.OrgPath("/admin/users")` returns `/api/v1/admin/users` on a custom domain. Give `Do` and `DoRaw` paths in that form.
- A path that starts with the `/orgs/...` segment of your own organization also works when the client has the organization ID, because the SDK removes the segment. It never changes a path of another organization.
- `RoutePath`, `BuildPath` and `Routes` stay in the platform form, with `/orgs/{orgId}`.

**The generated client.** The generated OpenAPI client puts `/orgs/{orgId}` in every path. On a custom domain, set `WithOrgID` as well and pass the same ID to the calls of the generated client. The HTTP client from `APIConfig` then removes the segment. Without the organization ID, the generated client cannot reach a custom domain.

## Upgrade Notes

- **Nothing changes for a client without a custom domain.** Every address on the LumoAuth host is the same as in v1.6.0. No exported function, type or field was removed or changed.
- **If your organization has a custom domain, pass it with `WithCustomDomain`, not with `WithBaseURL`.** A client that gets the domain as the base URL still sends `/orgs/...` paths, and the domain answers 404.
- **Set `CustomDomain` in place of `Issuer` in `AccessTokenVerifyOptions`.** Access tokens that are issued through the custom domain name the bare domain as issuer. A verifier that still trusts the platform issuer rejects them with `wrong_issuer`.
- **For AAuth, leave `VerifyOptions.Issuer` empty and set `CustomDomain`.** AAuth tokens name the platform form of the issuer. With `Issuer` set to the custom domain, `VerifyAuthToken` answers `untrusted issuer`.
- **Check your environment for `LUMOAUTH_CUSTOM_DOMAIN`.** When the variable is set, `New`, `NewAgent`, `NewWebAuth` and `NewAAuthClient` use the domain, also when you pass a base URL in code.
- **On a custom domain, call `aauth.ResolveIssuer(ctx)` before you read `aauth.Issuer()`.** The getter returns an empty string until the issuer is known.
- **A `TokenSource` of your own needs one more method on a custom domain:** `CustomDomain() string`, as `*Agent` has. `NewJITContext` and `NewDelegationChain` read it. Without the method their paths are in the platform form, which a custom domain answers with 404.
- **To use `client.Poppy`, set up a confidential application.** Add `poppy:verify` to its allowed scopes under **Applications**, and pass its credentials with `WithClientCredentials`. Without credentials, each call returns `ErrConfig` and sends no request. Without the scope, each call returns `ErrPermissionDenied`.
- **Set `PublicOrigin` to the address that personal agents call.** Add the base path that a proxy removes, for example `https://example.com/shop`. With a wrong value, every personal agent gets `invalid_session`, and the description names the URL (`htu`).
- **Verify each request once.** LumoAuth accepts each Session JWT one time. Put the middleware on a route once and pass the result inward. Set `AllowReplay` only when one request is verified in several places.
- **Each request waits for the verification call.** The call uses the timeout of the client, which is 30 seconds by default. Set a shorter one with `WithTimeout`.
- **Never write the error of a `client.Poppy` call to the response.** It is about your service, not about the personal agent.
- `Version` is now `"1.7.0"`, so the default `User-Agent` reports `1.7.0`.
- No dependency changes in this release. The module still requires Go 1.22.
